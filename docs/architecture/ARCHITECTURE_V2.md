## 🎯 v2.0 核心设计理念

**核心从"问题管理"迁移到"工程判断中台"**

- **v1.0**：工单是核心，判断卡是辅助工具
- **v2.0**：判断卡是核心资产，工单只是容器
- **价值**：判断卡是AI的训练数据、新人专业化的抓手、知识积累的载体

## 🔄 v1.0 → v2.0 结构性变化

### 1. 核心从"问题管理"迁移到"工程判断中台"

**v1.0**：
- 工单是核心实体
- 判断卡是辅助工具
- 知识散落在各个工单中

**v2.0**：
- **判断卡是核心资产**
- 工单只是容器，承载判断过程
- 判断卡是AI的训练数据
- 判断卡是新人专业化的抓手
- 判断卡是知识积累的载体

**影响**：
- 判断卡库需要独立管理
- 判断卡版本控制
- 判断卡使用统计（命中率）
- 判断卡效果评估

### 2. 入口层增加"问诊式补全（缺失信息清单）"

**v1.0**：
- 工单提交时校验必填项
- 缺失信息需要人工追问

**v2.0**：
- **自动生成"缺失信息清单"**
- 问诊式补全（引导式填写）
- 减少无效往返
- 提升工单质量

**实现**：
- AI分析工单信息
- 识别缺失的关键信息
- 生成问诊式问题清单
- 引导用户补全

### 3. 新增"口径输出层"作为强约束

**v1.0**：
- 对外沟通自由发挥
- 沟通记录分散

**v2.0**：
- **统一对外话术模板**
- AI辅助生成草稿
- 客户可见版本（专业表达，固定结构）
- **所有对外消息必须落库**（硬规则）

**价值**：
- 避免"看起来不专业"
- 统一品牌形象
- 完整审计留痕

### 4. 知识库拆成"判断型（内部）+结论型（外放）"

**v1.0**：
- 单一知识库
- 内容混杂

**v2.0**：
- **判断型知识库（内部）**：
  - 症状→区分点→排查路径
  - 误判清单/最佳路径
  - 供工程师使用

- **结论型知识库（客户可见）**：
  - FAQ/操作指引
  - 已验证方案
  - 版本适配与风险提示
  - 供客户自助服务

**价值**：
- 知识库是"判断工具"，不是"文章库"
- 内外分离，保护内部知识
- 提升客户自助能力

### 5. 结案强制"责任归因"，并可阈值触发整改任务

**v1.0**：
- 责任归因可选
- 整改任务手动创建

**v2.0**：
- **结案必须归因**（硬规则）
- **重复问题阈值触发CAPA**（硬规则）
- 让系统变成"减少火灾的机制"

**实现**：
- 结案时强制填写：`root_cause + responsibility_team + preventable`
- 30天≥N次同类问题 → 自动生成整改任务
- 整改任务跟踪闭环

### 6. AI 放在工程判断中台里当"副驾驶"

**v1.0**：
- AI功能分散
- 输出不可控

**v2.0**：
- **AI作为"副驾驶"**，不是"自动驾驶"
- 输出必须带证据引用（RAG）
- 不准自由发挥
- 只生成草稿，由人确认

**约束**：
- AI输出必须可追溯（证据来源）
- AI建议需要人工审核
- 低置信度自动升级

## ⚠️ v2.0 硬规则（系统级约束）

### 规则1：无判断卡不得结案

**规则**：`current_hypothesis + next_action` 为空 → 禁止 RESOLVED/CLOSED

**实现**：
```csharp
public async Task CloseTicketAsync(Guid ticketId)
{
    var ticket = await GetTicketAsync(ticketId);
    
    // 硬规则检查
    if (string.IsNullOrEmpty(ticket.CurrentHypothesis) || 
        string.IsNullOrEmpty(ticket.NextAction))
    {
        throw new BusinessRuleException(
            "无法结案：必须填写当前假设和下一步动作（关联判断卡）");
    }
    
    // ... 其他逻辑
}
```

### 规则2：低置信度自动升级

**规则**：`confidence <= 2` → `escalation_required = true` 并通知主管

**实现**：
```csharp
if (triageResult.Confidence <= 2)
{
    ticket.EscalationRequired = true;
    ticket.EscalatedTo = await GetSupervisorAsync();
    await NotifySupervisorAsync(ticket);
}
```

### 规则3：对外消息必须落库

**规则**：客户侧沟通必须通过"话术层"生成并记录（哪怕是复制粘贴）

**实现**：
- 所有对外沟通必须通过 `CommunicationGenerationService`
- 即使手动输入，也必须保存到 `customer_communications` 表
- 记录模板使用、生成内容、发送时间

### 规则4：结案必须归因

**规则**：`root_cause + responsibility_team + preventable` 必填

**实现**：
```csharp
public async Task CloseTicketAsync(Guid ticketId, CloseTicketRequest request)
{
    // 硬规则检查
    if (string.IsNullOrEmpty(request.RootCause) ||
        string.IsNullOrEmpty(request.ResponsibilityTeam) ||
        request.IsPreventable == null)
    {
        throw new ValidationException(
            "结案必须填写：根因、责任团队、是否可预防");
    }
    
    // ... 保存归因信息
}
```

### 规则5：重复问题阈值触发CAPA

**规则**：同型号+同归因，30天≥N次 → 自动生成整改任务并关联工单

**实现**：
```csharp
// 工单结案时触发检查
public async Task OnTicketClosedAsync(Guid ticketId)
{
    var ticket = await GetTicketAsync(ticketId);
    
    // 检查是否满足阈值
    var similarTickets = await FindSimilarTicketsAsync(
        deviceModel: ticket.Device.Model,
        rootCause: ticket.RootCause,
        withinDays: 30
    );
    
    if (similarTickets.Count >= CAPA_THRESHOLD)
    {
        await CreateCorrectiveActionAsync(ticket, similarTickets);
    }
}
```

## 🔧 技术实现要点

### 判断卡为核心的数据模型

```sql
-- 判断卡是核心实体
CREATE TABLE judgement_cards (
    jc_code VARCHAR(20) PRIMARY KEY,
    -- ... 判断卡字段
    usage_count INT DEFAULT 0,  -- 使用次数
    success_rate DECIMAL(5,2),  -- 成功率
    last_used_at TIMESTAMPTZ
);

-- 工单关联判断卡（必须）
ALTER TABLE tickets ADD COLUMN current_jc_code VARCHAR(20) NOT NULL;
ALTER TABLE tickets ADD COLUMN current_hypothesis TEXT NOT NULL;
ALTER TABLE tickets ADD COLUMN next_action TEXT NOT NULL;
ALTER TABLE tickets ADD COLUMN confidence SMALLINT CHECK (confidence >= 1 AND confidence <= 5);
```

### 问诊式补全实现

```csharp
public class MissingInfoService
{
    public async Task<List<QuestionItem>> GenerateMissingInfoChecklistAsync(
        Guid ticketId)
    {
        var ticket = await GetTicketAsync(ticketId);
        var jc = await GetJudgementCardAsync(ticket.CurrentJcCode);
        
        // AI分析：哪些关键信息缺失
        var missingInfo = await _aiService.AnalyzeMissingInfoAsync(ticket, jc);
        
        // 生成问诊式问题清单
        return missingInfo.Select(info => new QuestionItem
        {
            Question = info.Question,
            Type = info.Type,  // yes_no, number, text, file
            Required = info.Required,
            Hint = info.Hint
        }).ToList();
    }
}
```
