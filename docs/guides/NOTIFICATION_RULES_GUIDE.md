# 通知规则配置指南

本文档说明如何配置工单通知规则，实现自动通知相关人员。

## 📋 概述

通知规则系统允许在**客户级别**、**项目级别**或**设备级别**配置工单事件触发时自动通知的人员。支持按角色（项目经理、销售、工程师、管理层等）或直接选择用户/群组进行通知。

## 🎯 配置层级

### 1. 客户级别

为整个客户配置默认通知规则，适用于该客户下的所有项目和设备。

**适用场景**：
- 客户有固定的对接人员（销售、客服）
- 客户问题需要通知管理层

**配置位置**：客户管理 → 客户详情 → 通知规则

### 2. 项目级别

为特定项目配置通知规则，优先级高于客户级别。

**适用场景**：
- 项目有专门的项目经理和技术团队
- 项目有特定的沟通群组

**配置位置**：项目管理 → 项目详情 → 通知规则

### 3. 设备级别（可选）

为特定设备配置通知规则，优先级最高。

**适用场景**：
- 关键设备需要特殊关注
- 设备有专门的维护团队

**配置位置**：设备管理 → 设备详情 → 通知规则

## 🔔 通知场景

可配置以下场景的自动通知：

| 场景 | 触发时机 | 说明 |
|------|---------|------|
| **工单提交** | 工单状态变为 Submitted | 新工单创建并提交 |
| **工单分诊** | 工单状态变为 Triage | 高级工程师开始分诊 |
| **解决方案发布** | SOL 发布 | 解决方案已发布，等待验证 |
| **验证完成** | 验证结果提交 | 现场验证完成 |
| **工单关闭** | 工单状态变为 Closed | 工单已关闭 |

## 👥 通知对象选择

### 按角色选择

系统支持以下角色类型：

- **项目经理** (Project Manager)
- **销售** (Sales)
- **工程师** (Engineer)
- **管理层** (Management)
- **客服** (Customer Service)
- **技术主管** (Tech Lead)
- **自定义角色**

**角色匹配规则**：
- 系统根据企业微信用户的**标签**和**部门**匹配角色
- 一个用户可能匹配多个角色
- 通知时会自动去重（同一用户只通知一次）

### 直接选择用户

可以从企业微信通讯录直接选择特定用户：
- 支持搜索用户
- 支持按部门筛选
- 支持多选

### 选择群组

可以选择企业微信群组：
- 显示所有可用的群组
- 支持搜索
- 支持多选

## 📝 配置步骤

### 步骤 1: 进入配置页面

1. 登录 Web 管理端
2. 进入"项目管理"或"客户管理"
3. 选择要配置的项目/客户
4. 点击"通知规则"标签

### 步骤 2: 创建通知规则

1. 点击"新建通知规则"
2. 选择通知场景（如"工单提交"）
3. 选择通知对象：
   - 勾选角色（如：项目经理、销售）
   - 或直接选择用户
   - 或选择群组
4. 预览通知内容
5. 点击"保存"

### 步骤 3: 验证配置

1. 创建测试工单
2. 提交工单
3. 检查配置的人员是否收到通知

## 🎨 配置示例

### 示例 1: 项目级别配置

**场景**：项目 P1 的工单提交时，通知项目经理和技术讨论群

**配置**：
```json
{
  "ruleLevel": "project",
  "projectId": "project-p1-uuid",
  "triggerEvent": "ticket_submitted",
  "recipientsConfig": {
    "roles": ["project_manager"],
    "chatIds": ["tech-discussion-group"]
  }
}
```

### 示例 2: 客户级别配置

**场景**：客户 A 的所有工单提交时，通知销售和客服

**配置**：
```json
{
  "ruleLevel": "customer",
  "customerId": "customer-a-uuid",
  "triggerEvent": "ticket_submitted",
  "recipientsConfig": {
    "roles": ["sales", "customer_service"]
  }
}
```

### 示例 3: 多场景配置

**场景**：解决方案发布时，通知项目经理和工程师

**配置**：
```json
{
  "ruleLevel": "project",
  "projectId": "project-p1-uuid",
  "triggerEvent": "solution_published",
  "recipientsConfig": {
    "roles": ["project_manager", "engineer"]
  }
}
```

## 🔄 规则优先级

当多个层级的规则都存在时，按以下优先级执行：

```
设备级别 > 项目级别 > 客户级别
```

**示例**：
- 客户 A 配置：通知销售
- 项目 P1 配置：通知项目经理
- 设备 D1 配置：通知工程师

**结果**：设备 D1 的工单提交时，只通知工程师（设备级别优先级最高）

## 📊 通知内容

通知消息包含以下信息：

- 工单编号
- 客户名称
- 项目名称
- 设备信息（SN、型号）
- 问题描述
- 优先级
- 创建人
- 创建时间
- 可点击链接（查看详情）

**消息格式**：
```
【新工单】TK-20251222-001
━━━━━━━━━━━━━━━━━━━━
客户：某新能源汽车公司
项目：XX产线
设备：ATM-2000-01
问题：夹具到位后程序超时
优先级：P2
━━━━━━━━━━━━━━━━━━━━

━━━━━━━━━━━━━━━━━━━━
<a href="https://...">查看详情</a>
```

## 🔍 查看通知历史

可以在工单详情页面查看通知历史：

1. 进入工单详情
2. 点击"通知日志"标签
3. 查看所有通知记录：
   - 通知时间
   - 通知对象
   - 通知内容
   - 发送状态（成功/失败）

## ⚙️ 角色映射配置

系统需要配置企业微信标签到系统角色的映射关系。

**配置位置**：系统设置 → 企业微信集成 → 角色映射

**配置示例**：
```json
{
  "project_manager": {
    "wecomTags": ["项目经理", "PM"],
    "departments": ["项目管理部"]
  },
  "sales": {
    "wecomTags": ["销售", "Sales"],
    "departments": ["销售部"]
  },
  "engineer": {
    "wecomTags": ["工程师", "Engineer"],
    "departments": ["技术部", "工程部"]
  }
}
```

## ❓ 常见问题

**Q: 如何知道哪些用户匹配某个角色？**
A: 在配置页面选择角色后，系统会显示匹配的用户列表，可以预览。

**Q: 通知规则可以禁用吗？**
A: 可以，在规则列表中点击"禁用"即可，禁用后不会触发通知。

**Q: 可以配置多个通知规则吗？**
A: 可以，同一个场景可以配置多个规则，系统会合并所有规则的通知对象。

**Q: 通知失败怎么办？**
A: 系统会自动重试（最多3次），失败记录会保存到通知日志中。

**Q: 如何测试通知规则？**
A: 创建测试工单并提交，检查配置的人员是否收到通知。

## 📝 最佳实践

1. **客户级别配置通用规则**：为所有客户配置默认通知规则（如通知客服）
2. **项目级别配置特定规则**：为重要项目配置专门的通知规则
3. **避免过度通知**：不要配置太多通知对象，避免信息过载
4. **定期检查规则**：定期检查通知规则是否仍然有效
5. **使用群组**：对于需要多人协作的场景，使用群组通知更高效
