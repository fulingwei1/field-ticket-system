## 🎯 业务特点分析

### 核心业务流程

```
工单创建（现场工程师）→ 分诊（高级工程师+判断卡）→ 解决方案发布 
→ 现场验证（现场工程师）→ 结案 → 知识沉淀（判断卡）
```

### 关键角色职责

1. **现场工程师（FieldEngineer）**
   - 快速创建工单（2分钟内）
   - 上传证据（照片、视频、日志）
   - 执行验证
   - 客户沟通

2. **高级工程师（SeniorEngineer）**
   - 工单分诊
   - 创建/关联判断卡
   - 发布解决方案
   - 知识沉淀

3. **客服（CS）**
   - 工单跟进
   - 客户沟通
   - 催办协调

### 核心资产

- **判断卡（Judgement Card）**：核心知识资产
- **解决方案（SOL）**：已验证的解决方案
- **工单数据**：问题诊断和解决的历史记录

## 📊 绩效指标体系设计

### 一、工单处理效率维度

#### 1.1 工单创建质量

**指标名称**：工单创建完整度（Ticket Creation Completeness）

**计算公式**：
```
工单创建完整度 = (完整工单数 / 总工单数) × 100%
```

**完整工单标准**：
- ✅ 必填字段完整（设备、问题域、步骤、版本）
- ✅ 事实表填写完整（YES/NO问卷）
- ✅ 至少上传1个证据（照片/视频/日志）
- ✅ 无缺失信息清单

**采集方式**：
- 工单提交时自动检查
- 系统自动计算完整度

**目标值**：≥ 95%

**权重**：15%

---

#### 1.2 工单创建及时性

**指标名称**：现场问题反馈及时率（Field Feedback Timeliness）

**计算公式**：
```
及时反馈率 = (及时反馈的工单数 / 总工单数) × 100%
```

**及时标准**：
- 问题发生到工单创建时间 ≤ 2小时（紧急）
- 问题发生到工单创建时间 ≤ 24小时（一般）

**采集方式**：
- 工单创建时间 - 问题发生时间
- 系统自动计算

**目标值**：≥ 90%

**权重**：10%

---

#### 1.3 工单响应速度

**指标名称**：工单响应及时率（Ticket Response Timeliness）

**计算公式**：
```
响应及时率 = (及时响应的工单数 / 分配的工单数) × 100%
```

**及时标准**：
- 工单分配后首次响应时间 ≤ 30分钟（紧急）
- 工单分配后首次响应时间 ≤ 2小时（一般）

**采集方式**：
- 首次评论/追问回复时间 - 工单分配时间
- 系统自动记录

**目标值**：≥ 95%

**权重**：15%

---

#### 1.4 追问回复及时性

**指标名称**：追问回复及时率（Follow-up Response Rate）

**计算公式**：
```
追问回复及时率 = (及时回复的追问数 / 总追问数) × 100%
```

**及时标准**：
- 追问发出后回复时间 ≤ 4小时（工作日）
- 追问发出后回复时间 ≤ 24小时（非工作日）

**采集方式**：
- 追问回复时间 - 追问发出时间
- 系统自动记录

**目标值**：≥ 90%

**权重**：10%

---

### 二、问题解决能力维度

#### 2.1 一次解决率

**指标名称**：一次解决率（First Time Resolution Rate）

**计算公式**：
```
一次解决率 = (一次解决工单数 / 总处理工单数) × 100%
```

**一次解决标准**：
- 工单从Submitted到Closed，无Reopened状态
- 验证结果一次通过（PASS）

**采集方式**：
- 工单状态流转记录
- 验证结果记录

**目标值**：≥ 70%

**权重**：20%

---

#### 2.2 平均解决时间

**指标名称**：平均工单解决时间（Average Resolution Time）

**计算公式**：
```
平均解决时间 = Σ(工单解决时间) / 已解决工单数

工单解决时间 = 工单关闭时间 - 工单创建时间
```

**采集方式**：
- 工单创建时间和关闭时间
- 系统自动计算

**目标值**：
- 紧急工单：≤ 24小时
- 一般工单：≤ 72小时

**权重**：15%

---

#### 2.3 验证通过率

**指标名称**：解决方案验证通过率（Solution Verification Pass Rate）

**计算公式**：
```
验证通过率 = (验证通过的工单数 / 总验证工单数) × 100%
```

**采集方式**：
- 验证结果记录（PASS/FAIL）
- 系统自动统计

**目标值**：≥ 85%

**权重**：10%

---

#### 2.4 重复问题率

**指标名称**：重复问题率（Repeat Problem Rate）

**计算公式**：
```
重复问题率 = (重复问题工单数 / 总工单数) × 100%
```

**重复问题定义**：
- 同一设备30天内出现相同问题域的问题
- 同一客户30天内出现相同问题域的问题

**采集方式**：
- 工单去重和合并功能
- 系统自动识别

**目标值**：≤ 10%

**权重**：5%（负向指标，越低越好）

---

### 三、技术诊断能力维度

#### 3.1 判断卡使用准确率

**指标名称**：判断卡使用准确率（Judgement Card Accuracy）

**计算公式**：
```
判断卡准确率 = (正确使用判断卡的工单数 / 使用判断卡的工单数) × 100%
```

**正确使用标准**：
- 关联的判断卡与最终解决方案一致
- 判断卡的置信度 ≥ 3（1-5分制）
- 判断卡被验证为有效

**采集方式**：
- 判断卡关联记录
- 解决方案验证结果
- 系统自动评估

**目标值**：≥ 80%

**权重**：15%

---

#### 3.2 判断卡命中率

**指标名称**：判断卡命中率（Judgement Card Hit Rate）

**计算公式**：
```
判断卡命中率 = (命中判断卡的工单数 / 总工单数) × 100%
```

**命中标准**：
- 工单关联到判断卡
- 判断卡推荐引擎推荐成功

**采集方式**：
- 判断卡推荐记录
- 判断卡关联记录

**目标值**：≥ 60%

**权重**：10%

---

#### 3.3 AI建议采纳率

**指标名称**：AI建议采纳率（AI Suggestion Adoption Rate）

**计算公式**：
```
AI建议采纳率 = (采纳AI建议的工单数 / AI提供建议的工单数) × 100%
```

**采集方式**：
- AI辅助判断记录
- 工程师操作记录（是否采纳AI建议）

**目标值**：≥ 50%

**权重**：5%

---

#### 3.4 低置信度升级及时性

**指标名称**：低置信度升级及时率（Low Confidence Escalation Rate）

**计算公式**：
```
升级及时率 = (及时升级的工单数 / 低置信度工单数) × 100%
```

**及时标准**：
- 判断卡置信度 ≤ 2时，24小时内升级

**采集方式**：
- 判断卡置信度记录
- 工单升级记录

**目标值**：100%（硬规则）

**权重**：5%

---

### 四、知识贡献维度

#### 4.1 判断卡创建数量

**指标名称**：判断卡创建数量（Judgement Cards Created）

**计算公式**：
```
判断卡创建数量 = 统计周期内创建的判断卡总数
```

**采集方式**：
- 判断卡创建记录
- 系统自动统计

**目标值**：≥ 5个/月（高级工程师）

**权重**：10%

---

#### 4.2 判断卡质量评分

**指标名称**：判断卡质量评分（Judgement Card Quality Score）

**计算公式**：
```
判断卡质量评分 = 系统自动评分（0-100分）
```

**评分标准**：
- 有hypothesis无eliminated_causes → 降级
- confidence=5但evidence=0 → 标红
- suspected_domain与next_action冲突 → 标记异常
- 判断卡被复用次数（越多越好）
- 判断卡验证通过率（越高越好）

**采集方式**：
- 判断卡质量评分系统
- 系统自动计算

**目标值**：≥ 70分

**权重**：15%

---

#### 4.3 判断卡复用贡献

**指标名称**：判断卡复用贡献度（Judgement Card Reuse Contribution）

**计算公式**：
```
复用贡献度 = Σ(创建的判断卡被复用次数) / 创建的判断卡数
```

**采集方式**：
- 判断卡使用历史
- 系统自动统计

**目标值**：≥ 3次/卡

**权重**：10%

---

#### 4.4 解决方案贡献

**指标名称**：解决方案贡献度（Solution Contribution）

**计算公式**：
```
解决方案贡献度 = (创建的解决方案数 × 0.5) + (验证通过的解决方案数 × 0.5)
```

**采集方式**：
- 解决方案创建记录
- 验证结果记录

**目标值**：≥ 10个/月（高级工程师）

**权重**：10%

## 📊 综合绩效评分模型

### 评分公式

```
综合绩效评分 = Σ(各项指标得分 × 权重) × 100

各项指标得分 = (实际值 / 目标值) × 100（上限100分）
```

### 绩效等级划分

| 综合评分 | 绩效等级 | 说明 |
|---------|---------|------|
| ≥ 90分 | 优秀（Excellent） | 表现突出，可作为标杆 |
| 80-89分 | 良好（Good） | 表现良好，达到预期 |
| 70-79分 | 合格（Average） | 基本达标，有改进空间 |
| 60-69分 | 待改进（Below Average） | 未达标，需要重点关注 |
| < 60分 | 不合格（Poor） | 严重不达标，需要干预 |

## 🔍 数据采集方式

> **重要原则**：所有绩效指标数据均从客服工程师的日常工作中自动采集，**无需额外填写**，不增加工作量。

### 自动采集指标（100%自动采集，无需人工填写）

#### 1. 工单相关指标（自动采集）

**数据来源**：工单系统自动记录

- ✅ **工单创建时间**：`tickets.created_at`
- ✅ **工单提交时间**：`tickets.submitted_at`
- ✅ **工单关闭时间**：`tickets.closed_at`
- ✅ **工单状态流转**：`ticket_status_history` 表自动记录
- ✅ **工单关联信息**：`tickets.device_id`, `tickets.customer_id`, `tickets.project_id`
- ✅ **工单完整度**：系统自动检查必填字段、事实表、附件
- ✅ **问题发生时间**：`tickets.problem_occurred_at`（工单创建时填写，属于正常流程）

**采集方式**：数据库自动记录，无需额外操作

---

#### 2. 判断卡相关指标（自动采集）

**数据来源**：判断卡系统自动记录

- ✅ **判断卡创建记录**：`judgement_cards.created_at`, `judgement_cards.created_by`
- ✅ **判断卡使用记录**：`tickets.judgement_card_id`（工单关联判断卡时自动记录）
- ✅ **判断卡质量评分**：系统自动计算（基于判断卡内容、结构、逻辑）
- ✅ **判断卡命中率**：判断卡推荐引擎自动记录推荐结果
- ✅ **判断卡复用次数**：`jc_usage_history` 表自动记录每次使用
- ✅ **判断卡置信度**：`judgement_cards.confidence`（分诊时自动填写）

**采集方式**：系统自动记录，无需额外操作

---

#### 3. 解决方案相关指标（自动采集）

**数据来源**：解决方案系统自动记录

- ✅ **解决方案创建**：`solutions.created_at`, `solutions.created_by`
- ✅ **解决方案发布**：`solutions.published_at`
- ✅ **验证结果**：`tickets.verification_result`（现场工程师提交验证时自动记录）
- ✅ **验证时间**：`tickets.verified_at`
- ✅ **验证通过/失败**：`tickets.verification_status`（PASS/FAIL）

**采集方式**：系统自动记录，无需额外操作

---

#### 4. 响应和沟通指标（自动采集）

**数据来源**：系统交互自动记录

- ✅ **首次响应时间**：`ticket_comments.created_at`（第一条评论时间）- 工单分配时间
- ✅ **追问回复时间**：`follow_up_questions.answered_at` - `follow_up_questions.created_at`
- ✅ **客户沟通记录**：`customer_communications` 表（通过口径输出层自动记录）

// 自动计算工单处理时间
public TimeSpan CalculateResolutionTime(Ticket ticket)
{
    return ticket.ClosedAt - ticket.CreatedAt;
}

// 自动计算响应时间
public TimeSpan? CalculateResponseTime(Ticket ticket)
{
    var firstComment = ticket.Comments
        .OrderBy(c => c.CreatedAt)
        .FirstOrDefault();
    
    if (firstComment == null) return null;
    
    return firstComment.CreatedAt - ticket.AssignedAt;
}
```

// 基于工单处理记录自动生成工作日志
public async Task<WorkLog> GenerateWorkLogAsync(
    Guid engineerId,
    DateTime logDate)
{
    // 获取当日处理的工单
    var tickets = await GetTicketsByEngineerAndDateAsync(
        engineerId, logDate);
    
    // 获取当日创建的判断卡
    var judgementCards = await GetJudgementCardsByEngineerAndDateAsync(
        engineerId, logDate);
    
    // 获取当日发布的解决方案
    var solutions = await GetSolutionsByEngineerAndDateAsync(
        engineerId, logDate);
    
    // 自动生成工作日志
    return new WorkLog
    {
        EngineerId = engineerId,
        LogDate = logDate,
        WorkSummary = GenerateSummary(tickets, judgementCards, solutions),
        WorkDetails = GenerateDetails(tickets, judgementCards, solutions),
        TicketsHandled = tickets.Count,
        TicketsResolved = tickets.Count(t => t.Status == TicketStatus.Closed),
        JudgementCardsCreated = judgementCards.Count,
        SolutionsPublished = solutions.Count,
        TotalWorkHours = CalculateWorkHours(tickets),
        RelatedTicketIds = tickets.Select(t => t.TicketId).ToArray()
    };
}
```
