# 企业微信小程序版本规划

> **版本**：v2.0+  
> **日期**：2025-12-22  
> **目标**：实现Web、移动端App、企业微信小程序三端打通，重点打通数据录入功能

---

## 🎯 规划目标

### 核心目标

1. **三端打通**：Web管理端、移动端App、企业微信小程序
2. **数据录入统一**：三个平台的数据录入功能完全打通
3. **数据一致性**：三个平台的数据实时同步
4. **用户体验统一**：三个平台的交互体验保持一致

### 业务价值

- **降低使用门槛**：企业微信小程序无需安装，即开即用
- **提高覆盖率**：覆盖更多用户场景（轻量级操作）
- **数据统一**：所有平台数据统一管理，避免数据孤岛
- **灵活选择**：用户可以根据场景选择最适合的平台

## 🏗️ 技术架构

### 三端统一架构

```
┌─────────────────────────────────────────────────────────────┐
│                     统一后端API层                            │
│              .NET 8 + ASP.NET Core Minimal API              │
│                  PostgreSQL + Redis + MinIO                 │
└──────────────────┬──────────────────────────────────────────┘
                   │
        ┌──────────┼──────────┐
        │          │          │
┌───────▼───┐ ┌───▼────┐ ┌───▼──────────────┐
│ Web管理端  │ │移动端App│ │企业微信小程序      │
│ React 18  │ │Flutter │ │原生小程序框架      │
│           │ │        │ │                  │
│ 完整功能   │ │完整功能 │ │核心功能（数据录入）│
└───────────┘ └────────┘ └──────────────────┘
```

### 技术选型

| 平台 | 技术栈 | 说明 |
|------|--------|------|
| **Web管理端** | React 18 + Ant Design 5 | 保持不变 |
| **移动端App** | Flutter 3.x | 保持不变 |
| **企业微信小程序** | 原生小程序框架 / uni-app | 新增 |

### 数据同步策略

**实时同步**：
- 所有数据录入操作实时同步到后端
- 使用WebSocket或轮询实现实时更新
- 数据冲突处理：最后写入优先（或时间戳优先）

**离线支持**：
- 移动端App：完整离线支持
- 小程序：受限离线支持（本地缓存）
- Web端：无离线支持

## 🔧 技术实现方案

### 小程序框架选择

#### 方案1：原生小程序框架（推荐）

**优点**：
- 性能好，体验流畅
- 官方支持，文档完善
- 企业微信小程序API完整

**缺点**：
- 需要单独开发
- 代码无法复用

**技术栈**：
- 原生小程序框架
- TypeScript
- 企业微信小程序API

#### 方案2：uni-app

**优点**：
- 一套代码多端（小程序、H5、App）
- 代码可部分复用

**缺点**：
- 性能略差
- 企业微信小程序支持可能不完整

**技术栈**：
- uni-app
- Vue 3
- TypeScript

#### 方案3：Taro

**优点**：
- React语法，与Web端技术栈一致
- 代码可部分复用

**缺点**：
- 企业微信小程序支持需要验证

**技术栈**：
- Taro
- React
- TypeScript

**推荐**：方案1（原生小程序框架），确保最佳体验和完整功能支持

### 数据录入统一接口

#### API设计

**统一接口规范**：
```csharp
// 工单创建（三端共用）
POST /api/tickets
{
  "device_id": "uuid",
  "domain": "C",
  "step_code": "Step_120",
  "facts_json": {...},
  "attachments": [...],
  "platform": "web|mobile|miniprogram"  // 标识来源平台
}

// 事实表填写（三端共用）
PUT /api/tickets/{ticketId}/facts
{
  "facts_json": {...},
  "platform": "web|mobile|miniprogram"
}

// 附件上传（三端共用）
POST /api/tickets/{ticketId}/attachments
{
  "file": "base64|multipart",
  "platform": "web|mobile|miniprogram"
}

// 验证结果提交（三端共用）
POST /api/tickets/{ticketId}/verification
{
  "result": "pass|fail",
  "checklist": [...],
  "evidence": [...],
  "platform": "web|mobile|miniprogram"
}
```

#### 数据同步机制

**实时同步**：
- WebSocket连接（Web端、App端）
- 小程序使用轮询（每5秒）或长连接
- 数据变更实时推送

**冲突处理**：
- 时间戳优先
- 最后写入优先
- 冲突时提示用户

## 🔄 数据打通方案

### 统一数据模型

**三端共用数据模型**：
- 工单数据模型
- 事实表数据模型
- 附件数据模型
- 验证结果数据模型

**平台标识**：
- 每个数据操作记录来源平台
- 用于统计和分析

### 数据同步流程

```
用户操作（任意平台）
    ↓
调用统一API
    ↓
后端处理并存储
    ↓
实时推送更新（WebSocket/轮询）
    ↓
其他平台自动更新
```

### 数据一致性保障

1. **后端统一校验**：所有数据校验在后端统一处理
2. **事务保证**：关键操作使用数据库事务
3. **版本控制**：数据版本管理，支持冲突检测
4. **审计日志**：记录所有数据操作，支持追溯
