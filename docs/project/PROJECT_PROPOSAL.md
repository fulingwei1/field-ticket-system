> **文档版本**：1.0  
> **日期**：2025-12-22

---

## 📋 执行摘要

### 项目背景

非标自动化设备售后服务面临的核心挑战：
- 现场工程师经验不足，问题描述不准确
- 高级工程师需要反复追问，效率低下
- 经验无法沉淀，新人培养困难
- 问题重复发生，缺乏系统性改进

### 项目目标

**v2.0 目标**：让系统"能用"
- 现场工程师2分钟内完成问题提交
- 高级工程师不依赖电话追问即可远程定位
- 全链路可追溯

**v2.1 目标**：让系统"不会坏"
- 防系统退化（质量保障）
- 防经验流失（版本化、追溯）
- 防形式主义（硬规则、校验）

**v2.2-v2.3 目标**：让系统成为"长期资产"
- 管理科学化
- 组织记忆积累
- 持续改进机制

### 核心价值

| 对现场工程师 | 对高级工程师 | 对管理层 | 对公司 |
|------------|------------|---------|--------|
| 快速上报（2分钟） | 远程定位（无需追问） | 数据可视化 | 知识资产积累 |
| 引导式填写 | AI辅助判断 | 科学管理 | 持续改进 |
| 离线支持 | 判断卡复用 | 人才梯队建设 | 长期护城河 |

#### v2.0 核心功能（Sprint 1-3）

**Sprint 1: MVP闭环（2周）**
- 企业微信登录认证
- 工单创建和提交

- 问诊式补全缺失信息清单

**Sprint 2: 可用性增强（2周）**
- 离线草稿和补传队列
- 附件断点续传
- 判断卡推荐引擎
- 基础统计看板
- AI辅助判断系统
- 口径输出层
- 工单去重和合并
- **判断卡质量评分系统（v2.1 P0）**
- **判断轨迹版本化（v2.1 P0）**
- **设备配置快照和差异提示（v2.1 P0）**
- **最近变更自动关联（v2.1 P0）**
- **不可复现状态管理（v2.1 P1）**
- **潜在风险挂起功能（v2.1 P1）**

**Sprint 3: 体验优化（2周）**
- 设备二维码和扫码
- 客户沟通模板
- 工单全文搜索
- 数据导出功能
- 责任归因系统
- 整改任务系统
- **工程师负载统计（v2.1 P2）**
- **新人成长曲线可视化（v2.1 P2）**
- **知识有效期和版本绑定（v2.1 P3）**
- **知识来源追溯（v2.1 P3）**
- **KPI反作弊预警（v2.1 P3）**

### 技术架构

- **后端**：.NET 8 + ASP.NET Core Minimal API + EF Core 8
- **前端**：React 18 + Ant Design 5
- **移动端**：Flutter 3.x
- **数据库**：PostgreSQL 16 + pgvector（向量数据库）
- **缓存**：Redis 7
- **对象存储**：MinIO
- **AI**：Azure OpenAI / OpenAI API（RAG）
- **部署**：Docker Compose

## ⚠️ 风险与应对

| 风险 | 影响 | 概率 | 应对措施 |
|------|------|------|---------|
| 企业微信API限制 | 高 | 中 | 实现缓存、队列、重试机制 |
| AI效果不达预期 | 中 | 中 | 先做规则引擎，AI作为增强 |
| 用户接受度低 | 高 | 低 | 充分培训、逐步推进、收集反馈 |
| 数据质量问题 | 高 | 中 | v2.1质量保障机制 |
| 开发进度延期 | 中 | 中 | 分阶段交付，MVP优先 |
