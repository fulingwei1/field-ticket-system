# 现场设备问题跟踪管理 - 模板分析和改进建议

## 一、现有模板评估

### 1.1 模板优点 ✅

**好的方面：**

1. **记录基本信息完整**
   - ✓ 客户信息（客户名称、项目号、行业类型）
   - ✓ 设备信息（设备类型、项目名称）
   - ✓ 人员追溯（责任人、涉及部门）

2. **问题层级清晰**
   - ✓ 一条主记录（一个项目）
   - ✓ 多条子记录（该项目下的多个问题）
   - ✓ 问题描述和处理效果配对

3. **部门归属明确**
   - ✓ 有"部门归属"和"责任人"字段
   - ✓ 便于追踪各部门的工作量

4. **包含处理细节**
   - ✓ "现场异常描述" - 问题是什么
   - ✓ "处理效果及图片" - 怎么解决的
   - ✓ 跟进起始日期 - 什么时候处理的

---

### 1.2 模板问题 ⚠️

#### 问题1：【表头不一致】- 严重
**现象**：
- 1月文件：23列（包含"销售金额"、"下单日期"等）
- 11月文件：19列（没有"销售金额"、列序不同）
- Q1/Q2/Q3文件：结构又不一样

**影响**：
- 数据无法统一汇总分析
- 月度对比时字段对不上
- 新员工容易填错

**改进建议**：
```
统一为标准模板：
Column 1-5：基础信息（人员、设备、客户、项目名、项目号）
Column 6-8：数量和财务（数量、销售金额、成本）
Column 9-12：时间信息（下单日、要求交货日、实际交货日、交货延期天数）
Column 13-15：问题追踪（现场异常描述、处理效果、处理部门）
Column 16-18：验证信息（验证状态、客户反馈、满意度评分）
Column 19-20：后续信息（关联工单号、知识库ID）
```

---

#### 问题2：【日期格式混乱】- 严重
**现象**：
- 有些写"2025.9"（年月）
- 有些写"2025.10.11"（年月日）
- 有些写"2025-10-11"（带短划线）
- Excel自动转换导致显示不一致

**影响**：
- 难以排序和比较
- 无法计算处理周期（精度不足）
- 数据导入系统时出错

**改进建议**：
```
统一为：YYYY-MM-DD 格式
示例：
- 下单日期：2025-01-15
- 要求交货：2025-03-15
- 实际交货：2025-03-20
- 跟进开始：2025-03-20
- 跟进完成：2025-03-25

这样可以计算：
- 交货延期：实际 - 要求 = 5天
- 处理周期：跟进完成 - 跟进开始 = 5天
```

---

#### 问题3：【问题组织不清】- 严重
**现象**：
当前格式（一个项目多个问题时）：
```
Row 1: 王志红 | 单机 | TTi | 991116331 | PJ250820343 | ... | 铭牌未安装 | 反馈计工制作铭牌
Row 2: (空) | (空) | (空) | (空) | (空) | ... | 取料Z轴不水平 | 重新调整治具水平
Row 3: (空) | (空) | (空) | (空) | (空) | ... | 仪器未安装 | 安装3561仪器通电
Row 4: (空) | (空) | (空) | (空) | (空) | ... | NG气缸反向 | 气管接反
```

**问题**：
- ❌ 子行和父行的关联关系不清楚
- ❌ 多个问题之间的依赖关系看不出来
- ❌ 同一问题涉及多个部门时无法表示
- ❌ 无法统计"这个项目有多少问题"

**改进建议**：

**方案A - 分离表结构（推荐）**
```
表1：项目主表（PROJECT_MAIN）
├─ 项目号（主键）
├─ 项目名称
├─ 客户名称
├─ 设备类型
├─ 下单日期
├─ 要求交货日期
├─ 实际交货日期
├─ 销售金额
└─ 项目状态（未交付/已交付/已验证/有问题）

表2：现场问题表（FIELD_PROBLEM）
├─ 问题ID（自动生成）
├─ 项目号（外键，关联PROJECT_MAIN）
├─ 问题序号（同一项目下的第几个问题）
├─ 问题分类（硬件/软件/工艺/其他）
├─ 问题描述
├─ 发现日期
├─ 处理状态（待处理/处理中/已完成/已验证）
├─ 负责部门
├─ 负责人
├─ 处理方案
├─ 完成日期
├─ 验证状态（未验证/验证中/验证通过/验证失败）
├─ 客户反馈
├─ 满意度评分
└─ 备注

优点：
✓ 关系清晰
✓ 一个项目有多少问题，一眼就知道
✓ 可以分析每个问题的完成度
✓ 易于导入数据库系统
✓ 便于按问题统计
```

**方案B - 结构化字段**
```
在Excel中添加隐藏列：
- 问题序号：1,2,3,4...
- 问题分组：问题ID（如P001-001, P001-002...）
- 问题状态：待处理/处理中/已完成/已验证

配合条件格式化，相同问题块使用相同背景色
```

#### 问题4：【状态信息缺失】- 中等
**现象**：
- 只有"跟进起始日期"和"跟进完成日期"
- 没有明确的"处理状态"字段

**问题状态应该包括**：
```
① 待分配：问题已上报，等待分配给工程师
② 处理中：工程师已分配并在处理
③ 待验证：工程师完成处理，等待现场验证
④ 验证中：现场正在验证方案
⑤ 已验证：现场验证通过，问题解决
⑥ 验证失败：现场验证失败，需要重新处理
⑦ 已关闭：问题已完全解决
```

**改进建议**：
```
添加列：处理状态 (单选)
  ☐ 待分配
  ☐ 处理中
  ☐ 待验证
  ☐ 验证中
  ☐ 已验证
  ☐ 验证失败
  ☐ 已关闭

添加列：最后更新日期
  用于追踪状态何时变更
```

---

#### 问题5：【验证反馈缺失】- 中等
**现象**：
- 没有"客户验证反馈"字段
- 没有"满意度评分"

**问题**：
- 无法衡量解决方案的有效性
- 无法评估客户满意度
- 无法追踪验证失败的原因

**改进建议**：
```
添加列：
1. 验证结果
   ☐ 通过
   ☐ 部分通过
   ☐ 失败

2. 验证反馈
   自由文本，记录客户的验证结果和评价

3. 满意度评分
   1 ☐ 2 ☐ 3 ☐ 4 ☐ 5 ☐
   或 不满意 | 一般 | 满意 | 很满意

4. 验证人员
   现场验证的是谁（客户侧的人）

5. 验证日期
   YYYY-MM-DD
```

---

#### 问题6：【部门和个人职责混乱】- 中等
**现象**：
- 既有"部门归属"，也有"责任人"
- 不清楚一个问题由哪个部门、哪个人负责
- 有些问题涉及多个部门，无法表示

**例子**：
```
项目1的问题1：
- 部门归属：机械设计
- 责任人：李维
是李维所在的机械设计部门，还是李维作为个人？

项目1的问题2：
- 硬件问题需要采购处理
- 但硬件问题涉及多个部门：采购、机械、电气
怎么记录？
```

**改进建议**：

```
新模板：
├─ 主负责部门：采购（主要责任方）
├─ 主负责人：金希倩（部门内的具体负责人）
├─ 协作部门1：机械设计（是否有其他部门参与）
├─ 协作人员1：曾伟立
├─ 协作部门2：（如果需要第三个部门）
└─ 备注：多部门协作，需要同步进展

这样可以：
✓ 清晰地指出谁是主要负责人
✓ 也能表示跨部门协作
✓ 便于追踪各部门的进度
```

---

#### 问题7：【交付时间字段混乱】- 中等
**现象**：
- 1月文件有："要求交货时间"、"实际交货时间（年）"、"实际交货时间（日）"、"预计完成交付时间"、"实际交付时间"
- 11月文件有："实际交货时间（月）"、"实际交货时间（日）"
- Q文件又有其他格式

**问题**：
- 字段太多且含义重复
- 分不清"交货"和"交付"的区别
- 无法计算延期天数

**改进建议**：
```
统一为这几个字段：

1. 订单日期：2025-01-15
   客户下单的日期

2. 要求交货日期：2025-03-15
   客户要求的交货日期（合同承诺）

3. 实际交货日期：2025-03-20
   实际交给客户的日期

4. 交货延期天数：=实际-要求=5天
   自动计算，便于统计

5. 要求安装调试完成日期：2025-03-25
   （如果需要现场安装调试）

6. 实际安装调试完成日期：2025-03-28
   （如果需要现场安装调试）

7. 安装延期天数：=实际-要求=3天

这样清晰明了，可以分别统计：
- 生产周期内的交货延期
- 现场安装的延期
```

---

#### 问题8：【缺少问题分类】- 低
**现象**：
- 所有问题混在一起，没有分类

**问题**：
- 无法分析最常见的问题类型
- 无法按问题类型进行改进

**改进建议**：
```
添加列：问题分类（多选）

选项：
☐ 硬件故障（零件坏了、连接松了等）
☐ 软件缺陷（功能不对、算法错误等）
☐ 工艺问题（参数不对、流程设计不合理）
☐ 设计问题（结构不合理、产品设计有缺陷）
☐ 安装问题（安装位置不对、调试不到位）
☐ 需求变更（客户改需求导致的问题）
☐ 配置问题（参数、版本不对等）
☐ 其他

这样可以统计：
- 硬件故障占30%
- 软件缺陷占40%
- ...
便于按最高频问题类型进行改进
```

---

#### 问题9：【关键时间成本无法统计】- 低
**现象**：
- 有跟进起始和截止日期，但没有计算字段
- 无法快速看出处理周期

**改进建议**：
```
添加计算列：

1. 处理周期（天）
   =跟进截止日期 - 跟进起始日期

2. 交货延期（天）
   =实际交货日期 - 要求交货日期

3. 逾期标志（是/否）
   如果交货延期 > 0，则=是，否则=否

这样可以快速找出：
- 哪些项目逾期了
- 处理周期最长的问题
- 平均处理周期是多少
```

---

#### 问题10：【无法追踪关联】- 低
**现象**：
- 一个问题无法关联到系统中的工单
- 无法关联到知识库中的类似问题
- 无法知道这个问题之前是否出现过

**改进建议**：
```
添加关联字段：

1. 是否已关联工单（是/否）
2. 关联工单号（如：TK-202501-001）
3. 是否已沉淀知识库（是/否）
4. 知识库ID（如：KB-2025-001）
5. 是否重复问题（是/否）
6. 相关历史问题（如果是重复的，记录之前的问题ID）

这样可以：
✓ 追踪问题在整个系统中的流转
✓ 快速发现重复问题
✓ 知道哪些问题已经沉淀到知识库
✓ 新问题时可以自动推荐相似的历史方案
```

### 2.2 推荐的分表结构（Multi-Sheet，更好）

**Sheet1: 项目主表（Project）**
```
列：
A: 项目号（主键）
B: 项目名称
C: 客户名称
D: 设备类型（线体/单机/其他）

J: 交货延期天数（=I-H）

```
列：
A: 问题ID（自动生成）

L: 处理方案
M: 处理完成日期（YYYY-MM-DD）
N: 处理周期天数（=M-F）
O: 验证状态（未验证/验证通过/验证失败）
P: 验证反馈
Q: 满意度评分（1-5）
R: 关联工单号
S: 知识库ID
T: 是否重复问题（是/否）
U: 相关历史问题ID
V: 备注
```

**Sheet3: 统计汇总**
```
行：
- 项目总数
- 问题总数
- 平均每个项目的问题数
- 按问题分类的统计
- 按处理状态的统计
- 按部门的问题分布
- 平均处理周期
- 平均满意度评分
- 交货延期统计
```

## 三、具体案例分析

### 3.1 案例1：项目PJ250820343（TTi平衡测试机）

**当前数据：**
```
主记录：
人员: 林潇伟
设备: 单机
客户: TTi
项目: 991116331-平衡测试机(E类)
项目号: PJ250820343
发现日期: 2025-10-08
部门: 生产
负责人: 方康敬

子记录（问题）：
1. 铭牌未安装
   处理: 反馈计工制作铭牌寄现场安装
   
2. 取料Z轴吸电芯治具左右高低不水平
   处理: 重新调整取料治具水平
   
3. 3561仪器未安装
   处理: 安装3561仪器通电测试正常
   
4. NG气缸点动运动方向取反
   处理: 气管接反
```

**问题分析：**

❌ **问题1：不知道各个问题的完成日期**
- 只知道"跟进起始日期：2025.10.8"，"跟进截止日期：2025.10.31"
- 不知道4个问题各自什么时候完成的
- 不知道哪个问题耗时最长

⚠️ **改进建议：**
```
添加每个问题的：
问题1: 铭牌未安装
  - 发现日期：2025-10-08
  - 完成日期：2025-10-10（预计）
  - 处理周期：2天
  - 状态：待验证

问题2: 取料Z轴不水平
  - 发现日期：2025-10-08
  - 完成日期：2025-10-12（预计）
  - 处理周期：4天
  - 状态：已验证

问题3: 仪器未安装
  - 发现日期：2025-10-08
  - 完成日期：2025-10-13（预计）
  - 处理周期：5天
  - 状态：已验证

问题4: 气缸方向错误
  - 发现日期：2025-10-08
  - 完成日期：2025-10-09（预计）
  - 处理周期：1天
  - 状态：已验证
```

❌ **问题2：看不出问题的优先级**
- 4个问题都是同等对待
- 但实际上气缸问题（1天）应该比仪器问题（5天）优先级高，因为更快解决

⚠️ **改进建议：**
```
添加优先级字段：
问题1（铭牌）：优先级=P4（非关键，安装后处理）
问题2（Z轴）：优先级=P1（关键，影响加载）
问题3（仪器）：优先级=P2（重要，影响检测）
问题4（气缸）：优先级=P1（关键，立即修复）

然后按优先级排序处理
```

❌ **问题3：不知道是否已验证通过**
- 只看到"处理效果"，但没有"验证结果"
- 不知道现场是否验证过了

问题1: 验证状态=未验证/验证中/已验证/验证失败
问题2: 客户反馈="已现场测试，运行正常"

  - 依赖关系：无

这样就能看出处理顺序：
第1阶段：先做问题3（硬件防护）
第2阶段：再做问题1（软件调试）

```

- 资源是否充足？

```

这样能看出：
- 总处理周期

```

❌ **问题3：无法追踪多个问题的整体进度**

- 11个问题中，有几个已完成？

- 有几个验证失败需要返工？

## 四、改进方案总结

### 4.1 快速改进（不用系统，Excel内改进）

**优先级：立即做**

1. **统一列名和列序**
   - 制定标准模板
   - 所有月份文件使用同样的列

2. **统一日期格式**
   - 所有日期改为 YYYY-MM-DD
   - 使用Excel的日期格式而不是文本

3. **分离一对多关系**
   - 项目表 + 问题表，用项目号关联
   - 使用颜色或分组来标识同一项目的问题

4. **添加关键字段**
   ```
   添加列：
   - 问题序号（项目内第几个问题）
   - 问题分类（硬件/软件/工艺等）
   - 处理状态（待处理/处理中/已完成/已验证）
   - 满意度评分（1-5分）
   - 处理周期（自动计算）
   - 是否延期（自动判断）
   ```

---

### 4.2 中期改进（Excel增强，引入一些自动化）

**优先级：1个月内**

1. **创建二级表结构**
   - Sheet1: 项目汇总表
   - Sheet2: 问题详细表
   - Sheet3: 统计分析表

2. **添加数据透视表**
   ```
   统计维度：
   - 按客户统计问题数
   - 按部门统计问题数
   - 按问题分类统计
   - 按处理状态统计
   - 按月份趋势统计
   ```

3. **添加条件格式化**
   ```
   - 逾期项目用红色标记
   - 进行中用黄色标记
   - 已完成用绿色标记
   ```

4. **创建仪表盘**
   ```
   显示KPI：
   - 本月问题总数
   - 平均处理周期
   - 平均满意度
   - 按部门的问题分布
   - 问题分类分布
   ```

---

### 4.3 长期改进（构建专业管理系统）

**优先级：2-3个月内**

1. **建立现场问题管理系统**
   - 前面设计的"问题来源和收集机制"正好用上
   - 通过系统追踪问题的全生命周期

2. **自动化工作流**
   ```
   工作流：
   问题上报 → 自动分配 → 处理 → 验证 → 沉淀知识库
   ```

3. **知识库集成**
   - 自动识别重复问题
   - 推荐历史解决方案
   - 沉淀常见问题FAQ

4. **数据分析和改进**
   - 分析最常见的问题类型
   - 追踪各部门的响应速度
   - 持续改进流程
